# 혼주 소개 행 정렬 (Parent Intro Line Alignment) — 설계 문서

작성일: 2026-08-16
대상 파일: `index.html` (단일 파일 SPA, GitHub Pages)
대상 범위: GALLERY 01 "모시는 글" 하단 혼주 소개 블록 (210–213행)

## 목표

혼주 소개 두 줄의 **띄어쓰기를 국문 어법에 맞게 고치고**, 두 줄이 세로로
어긋나 보이는 문제를 해결한다. 문구·색·폰트는 그대로 두고 정렬만 바로잡는다.

## 현재 상태

```html
<div>이순규 · 장일란 <span style="color:#9a8c76;">의 아들</span> &nbsp;<b>종호</b></div>
<div>김주헌 · 유정연 <span style="color:#9a8c76;">의 딸</span> &nbsp;<b>희정</b></div>
```

세 가지 문제가 겹쳐 있다.

### 1. 관형격 조사 `의` 앞의 공백 (어법 오류)

"장일란 **의** 아들"처럼 조사가 앞말에서 떨어져 있다. 조사는 앞말에 붙여
써야 한다. 이 공백은 의도된 것이 아니라 회색 `<span>`을 여는 위치 때문에
생긴 부작용이다.

### 2. 두 줄의 세로 어긋남 (주 증상)

블록이 `text-align:center`인데 관계어가 "아들"(2글자) / "딸"(1글자)로 길이가
다르다. 중앙 정렬은 그 차이를 좌우로 반씩 나누므로 두 줄의 모든 요소가
어긋난다.

브라우저 실측값 (Gothic A1 300/500 로드 확인, `font-size:14px`):

| 항목 | 실측 |
|------|------|
| `의 아들` 폭 | 43.45px |
| `의 딸` 폭 | 30.11px |
| 관계어 길이 차 | **13.34px** (한글 1글자 advance) |
| `종호` 좌측 x | 318.48px |
| `희정` 좌측 x | 311.81px |
| **이름 열 어긋남** | **6.67px** (= 13.34 ÷ 2) |

부모 이름의 시작점도 같은 6.67px만큼 반대 방향으로 어긋난다.

### 3. 이름 앞 간격이 이중으로 지정됨

소스에 일반 공백과 `&nbsp;`가 연달아 있어 의도가 모호하다. 실측 간격은
**6.81px** (≈ 0.49em).

## 설계

바깥 `div`의 `text-align:center`는 유지하고, 안쪽에 `display:inline-grid`
블록을 넣어 3열 × 2행으로 배치한다.

- `inline-grid`는 내용만큼만 폭을 차지하므로 **블록 전체는 지금처럼 화면
  중앙**에 놓인다. 바깥 중앙 정렬 구조를 바꾸지 않는다.
- 열 폭을 `auto`로 두면 브라우저가 열별 최대 콘텐츠 폭을 계산한다. 2열 폭이
  "아들" 폭으로 결정되고 "딸"은 그 안에서 좌측 정렬되므로, **em 값을 추측하지
  않고도** 3열(이름)이 픽셀 단위로 일치한다. 폰트 메트릭에 의존하지 않는 것이
  고정폭(`width:2em`) 방식 대비 이 방식의 이점이다.

### 마크업

```html
<div data-reveal data-reveal-delay="160" style="margin-top:42px; padding-top:32px; border-top:1px solid #e0d6c4; text-align:center; font-family:'Gothic A1'; font-weight:300; font-size:14px; line-height:2.2; color:#5a5246;">
  <div style="display:inline-grid; grid-template-columns:auto auto auto; column-gap:.25em; justify-items:start; text-align:left;">
    <span>이순규 · 장일란<span style="color:#9a8c76;">의</span></span>
    <span style="color:#9a8c76;">아들</span>
    <b style="font-weight:500; margin-left:.25em;">종호</b>

    <span>김주헌 · 유정연<span style="color:#9a8c76;">의</span></span>
    <span style="color:#9a8c76;">딸</span>
    <b style="font-weight:500; margin-left:.25em;">희정</b>
  </div>
</div>
```

### 값 결정 근거

**`column-gap: .25em`** — 1열과 2열 사이는 `의`와 `아들` 사이의 **낱말
공백**이므로 실제 공백 문자 폭과 같아야 한다. Gothic A1 14px의 공백 실측폭은
3.43px = **0.245em**. 이보다 넓히면 어색한 낱말 간격이 된다.

**이름 앞 간격 = `column-gap .25em` + `margin-left .25em` ≈ 7px** — 현재
실측 간격 6.81px를 유지한다. 사용자가 제기한 문제는 정렬이지 간격 크기가
아니므로, 현행 여백감을 보존하는 쪽을 기본값으로 둔다. 시각 확인 단계에서
넓히는 편이 낫다고 판단되면 `margin-left`만 조정한다 (유일한 튜닝 지점).

**회색(`#9a8c76`) 범위를 `의`부터 시작** — 조사가 앞말에 붙으면서 `장일란`과
`의`가 한 단어가 되므로, 회색 `span`이 낱말 중간에서 열린다. `의`를 본문색으로
두면 회색 "아들/딸"과 분리되어 떠 보이므로, "관계어는 뮤트"라는 기존 의도를
유지한다.

**색·폰트·굵기·행간·구분선은 전부 현행 유지** — DESIGN.md 팔레트 밖의 값은
도입하지 않으며, 두 번째 악센트색도 추가하지 않는다.

### 줄바꿈 안전성

행 전체 폭 계산 (14px 기준):

| 요소 | 폭 |
|------|-----|
| `이순규 · 장일란의` | ≈ 106px |
| `아들` | ≈ 27px |
| `종호` | ≈ 27px |
| 간격 2개 | ≈ 7px |
| **합계** | **≈ 167px** |

섹션 좌우 패딩이 30px씩이므로 최소폭 320px 기기에서 가용 폭은 260px.
167px < 260px으로 여유가 있어 줄바꿈 위험은 없다. 실측으로 확인한다.

## 검증

이 저장소는 테스트 프레임워크가 없는 정적 사이트이므로 브라우저 실측으로
검증한다.

1. **정렬** — `종호`와 `희정`의 `getBoundingClientRect().left`가 **일치**하는지
   (현재 6.67px 차이 → 목표 0px). 부모 이름 시작점도 동일하게 확인.
2. **줄바꿈** — 375px과 320px 폭에서 두 행이 각각 한 줄로 유지되는지
   (행 높이가 `line-height` 1줄분을 넘지 않는지).
3. **어법** — 렌더된 텍스트에 `장일란 의` / `유정연 의` 같은 조사 앞 공백이
   없는지.
4. **육안** — 두 폭에서 스크린샷으로 여백감과 회색 대비가 기존과 어긋나지
   않는지.
5. **회귀** — `data-reveal` 애니메이션이 정상 동작하는지 (마크업 계층이
   한 단계 깊어지므로 리빌 대상 요소는 바깥 `div`에 그대로 유지).

## 범위 밖 (YAGNI)

- **관계어 표기 변경** — "아들/딸"을 "장남/장녀" 등으로 바꾸는 안은 검토했으나
  채택하지 않았다. 실제 형제 서열 확인이 필요하고, 문구 변경은 이번 요청
  범위가 아니다.
- **회색 대비 규정 재검토** — DESIGN.md는 `#9a8c76`(라벨 뮤트)를 장식 라벨
  전용으로 규정하고 정보 전달 텍스트 사용을 금지한다. "의 아들"은 정보성
  텍스트에 가까우므로 현행 마크업은 이 규정에서 벗어나 있다. 다만 이는 이번
  변경 이전부터 있던 상태이고 색을 바꾸면 블록 인상이 달라지므로, **현행을
  의도적으로 보존**한다. 색 자체를 손보려면 별도 논의가 필요하다.
- **다른 섹션의 유사 정렬** — "마음 전하실 곳" 계좌 행 등은 이번 대상이 아니다.
